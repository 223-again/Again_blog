 # 文章文件夹（博客真相源）

这个文件夹是博客文章的**唯一来源**。每篇文章是一个 `.md` 文件。
在 Obsidian 里把这个文件夹（或它的上级）当作库打开，正常写作即可。
写完在仓库根目录跑 `python sync.py`，文章就会同步进 `index.html`。

> 注意：`sync.py` 是**全量重建**——这里删掉一个 `.md`，博客上对应文章也会消失；
> 改了内容，博客上就会更新。以本文件夹为准。

## 文章格式

文件开头用 frontmatter 写元数据，下面写正文：

```markdown
---
title: 文章标题
cat: tech            # essay=随笔 / tech=技术 / life=生活
excerpt: 一两句话概括这篇文章
date: 2026-07-10     # 可选，缺省用文件修改日期
big: false           # 可选，true 时在首页显示为大卡片
---

## 这是一个二级标题

这是一个段落。行内代码用反引号，比如 `node --version`。

​```
node --version
npm --version
​```

> 这是一段引用。
```

## 正文语法

| 写法 | 效果 |
|------|------|
| `# ~ ######` 开头 | 标题 |
| `>` 开头 | 引用 |
| 三个反引号包起来 | 代码块（块内 `#`、`>` 均按原样，不解析） |
| `` `反引号` `` | 行内代码 |
| 普通文字 | 段落，空行分段 |

`<`、`>`、`&` 等符号在正文里会自动转义，直接写即可，无需手动处理。

## 分类对应

| cat | 显示名 |
|-----|--------|
| essay | 随笔 |
| tech | 技术 |
| life | 生活 |

## 同步流程

```bash
python sync.py          # 重建 index.html
python sync.py --check  # 只看有无变化，不写文件

git add -A && git commit -m "更新文章" && git push
```

推送到 `main` 后，GitHub Pages 约 1 分钟自动更新。
